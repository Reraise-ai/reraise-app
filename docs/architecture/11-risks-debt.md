# 11. Risks and technical debt

An honest list, kept current. A risk is something that may go wrong; technical debt is
something we already owe. Each entry names its mitigation or the way to pay it back.

## 11.1 Risks

| ID | Risk | Impact | Mitigation |
| --- | --- | --- | --- |
| RK-01 | **CI has never run on GitHub.** All workflows (lint and format, typecheck, the three-OS test matrix, audit, REUSE, gitleaks, CodeQL, docs build and deploy) were only run locally or not at all. Windows and macOS runners in particular may fail on paths, line endings or shell differences. | High: M0 is not done until CI is green; every "passes locally" in [verification](../verification.md) may turn red. | Push as soon as access works; fix the first run before any feature work; keep the status "passes locally; no CI run yet" until then. |
| RK-02 | **Push access to the GitHub repository is blocked.** Pull requests are simulated as local branches merged by the orchestrator. Branch protection, required checks, Dependabot, secret scanning with push protection, GitHub Pages, milestones and issues are not configured or verified. | High: the process guarantees of [ADR-0025](../adr/0025-engineering-process-and-quality-gates.md) exist on paper only. | Restore access; then configure branch protection and required checks, create milestones and issues per slice, and verify that the docs site deploys. |
| RK-03 | **Jev interface is to be defined by the owner.** | Medium: the connector shape may change. | The Jev connector is a stub behind the `ModelConnector` port and always behind the gate; nothing else depends on Jev ([ADR-0015](../adr/0015-two-thinking-levels.md)). |
| RK-04 | **The brand design system is pending.** | Medium: UI rework when it lands. | Design tokens only, no hard-coded colours or fonts, no component-library theme ([ADR-0019](../adr/0019-design-tokens-and-board-canvas.md)); the token check is still to be written (ADR-C09). |
| RK-05 | **Contracts are not on the trunk yet.** JSON Schemas, examples, OpenAPI, MCP tool schemas and the port interfaces are under review. These pages describe them as in progress. | Medium: M1 cannot start in parallel; review may change names used here. | Merge the contract branches; update these pages where names differ. |
| RK-06 | **Contract drift with adapters outside the repository**, notably the owner's store adapter. | Medium: silent incompatibility. | Conformance kit as the gate for every adapter; contract changes only through ADRs ([ADR-0005](../adr/0005-universal-adapter-architecture.md)). |
| RK-07 | **Mermaid C4 support is experimental.** The diagrams on these pages were checked by parsing and rendering them to SVG with Mermaid in a headless DOM, not by looking at them in a browser; C4 layouts may be cramped. | Low: diagrams may be hard to read. | Every diagram has a table with the same content next to it; fall back to flowcharts if the rendered C4 diagrams are unreadable. |
| RK-08 | **Concurrent edits from outside the product.** Sync tools, Git or other agents may change the same files while the service writes. | Medium: conflicts or lost updates. | Optimistic concurrency on `version` / `contentHash`, archive on rewrite, conflicts surfaced to the human ([ADR-0006](../adr/0006-files-are-the-truth.md)). |
| RK-09 | **Gate onboarding friction.** Default deny shows little to models until rules exist, which may push users to over-broad allow rules. | Medium: privacy weakened by configuration. | Onboarding explains per-card rules; cloud transfers still need per-transfer confirmation; OD-3 must make narrow rules easy. |
| RK-10 | **Prompt injection through card content.** Text from stores, sources or agents may contain instructions aimed at models or agents. | Medium. | Content is data, never instructions or markup ([ADR-0026](../adr/0026-security-defaults.md)); model answers return only as proposals a human reviews. |
| RK-11 | **Proposal fatigue.** Busy agents may flood the board with proposals, and humans may accept without reading. | Medium: provenance integrity depends on real review. | Proposals keep their author after acceptance; batch accept is a later UX concern and still per proposal underneath ([ADR-0011](../adr/0011-agent-moves-are-proposals.md)). |
| RK-12 | **Self-hosting moves "the device".** On a self-hosted server, stances and the gate log live on that server. | Medium. | Document it in the self-hosting guide; loopback default ([ADR-0026](../adr/0026-security-defaults.md)). |
| RK-13 | **Derived ids depend on the URI scheme.** Changing a store's `storeInstanceId` or id normalisation changes every derived id. | Medium: broken references. | The URI scheme is part of an adapter's stable contract ([ADR-0023](../adr/0023-core-domain-model.md)); conformance tests id stability. |
| RK-14 | **Case-insensitive file systems.** Store ids that differ only in case collide on Windows and macOS defaults. | Low to medium. | The reference adapter must detect and reject such collisions ([deployment 7.3](./07-deployment.md#73-portability-windows-macos-and-linux)). |
| RK-15 | **Build process relies on agents.** Most code and docs are written and reviewed by agents, with one human maintainer. | Medium: shared blind spots. | A second agent or model reviews every change; ADRs and checks make rules explicit; the owner decides what, money and irreversible matters. |

## 11.2 Technical debt

| ID | Debt | Pay back by |
| --- | --- | --- |
| TD-01 | **Vite override.** The root `package.json` forces `vitepress>vite` to `^7.3.2`, because VitePress 1.x bundles Vite 5 with known advisories that would fail the blocking audit. The repository therefore holds two Vite majors (7 for the docs, 8 for the board), and VitePress runs on a Vite version it was not released against. See [CONTRIBUTING](https://github.com/Reraise-ai/reraise-app/blob/main/CONTRIBUTING.md). | Remove the override when VitePress ships a Vite release without the advisories. |
| TD-02 | **Checks promised by ADRs but not written:** licence import direction, DCO and commit-title check, design-token check, MCP and HTTP parity, no-score field in rules results, gate defaults, MCP write-path check, loopback default, training opt-in (ADR-C07 to ADR-C16 in [verification](../verification.md#checks-promised-by-the-adrs)). | Write each check with the slice that first needs it; at the latest before M1 is called done. |
| TD-03 | **Markdown lint** is configured for `docs/adr` only and is not a CI job. | Extend to all docs and add the job. |
| TD-04 | **Skeleton duplication.** `apps/board` declares its own list of layers instead of importing it from `packages/core`. | Replace with the generated contract types in M1. |
| TD-05 | **MCP server without SDK.** `packages/mcp-server` contains only the tool names; the official SDK is not a dependency yet. | Add with the M1 MCP implementation. |
| TD-06 | **Coverage gate on almost no code.** The 90 % gate on `packages/core` measures a few lines today, so it proves little. | Grows meaningful as core logic lands in M1. |
| TD-07 | **Docs deploy from `main` only**, but nothing has been pushed, so the documentation site has never been published. | Resolved with RK-02. |
| TD-08 | **Open architecture decisions** OD-1 to OD-7 ([section 9.2](./09-decisions.md#92-open-decisions)). The pages use working assumptions for them. | ADRs before M1 (OD-1, OD-2, OD-3, OD-5, OD-6); owner decisions for OD-4 and OD-7. |
| TD-09 | **Frozen prototype deviates from the canon** (barometer, ingestion, four layers, ghost cards). | Kept as design reference only; superseded by the board app in M1 ([Board UX](../product/board-ux.md#prototype-v1-frozen-design-study)). |
